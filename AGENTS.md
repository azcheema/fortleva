## Vocabulary (law — the schema depends on it)

**Tenant** = a subscribing company · **Member** = a person who works at a tenant · **Client** = a customer *of a tenant* (a company record, never a login) · **Contact** = a person at a client (the portal principal) · **Platform** = the layer above all tenants. Never write "user" for both a Member and a Contact. In the UI a `WorkItem` is called a **Task**.

## Non-negotiable engineering rules

- **One DB seam.** All database access goes through `withTenant` / `withPlatform` / `withUser` from `@/db`. Never import `@/db/client` or the generated client outside `src/db` and `src/auth` (ESLint enforces it). `withPlatform` is importable only from `(platform)`, `jobs/`, `src/db` and tests.
- **Every new Prisma model** is registered in `MODEL_CLASSES` *and* exactly one `RLS_CLASSES` subclass in `src/db/model-registry.ts`, and ships a **hand-written migration** granting `app_runtime` and applying `ENABLE`+`FORCE ROW LEVEL SECURITY` with `tenant_isolation` plus `portal_deny` (class A) or `portal_gate` (class B). Never run `prisma migrate reset` or `prisma db push`.
- **Every mutation**: `requireAccess()` → `assertInScope()` → mutate → `audit.record()` **in the same transaction**. The action must already exist in `src/audit/catalog.ts`. *(One carve-out, 2026-08-21: a **rank-only reorder** — `moveItem` with no state change — writes neither an activity row nor an audit event, because rank is not a field anyone sees; the same rule as `updateItemFields`' routine edits. A move that also changes state audits `work_item.state_changed` as every state change does. Do not read this as licence to skip audit anywhere a person could see the change.)* *(Extended by founder decision 2026-09-12, for the item panel: a **routine field edit** writes a `WorkItemActivity` row and no audit event even when the field is one a client can see — the description, the milestone, labels, and creating or editing **your own** comment. Editing **someone else's** comment is not routine and audits `comment.edited_by_other`. Deletion, visibility and state are never routine.)*
- **Three namespaces, never mixed**: permission codes `resource:verb` (immutable forever — deprecate, never rename), audit actions `entity.verb`, portal capabilities `portal.area.verb`.
- **Visibility is safety-critical.** `INTERNAL` is the default everywhere; the portal gate is `client_id = app.client_id AND visibility = 'CLIENT_VISIBLE' AND portal_enabled`, enforced in the database. `portal_enabled` is trigger-derived from the project — never write it on a child row. The worst bug this product can have is a client seeing internal data.
- **Portal reads** run under the contact principal via RLS; contact-*caused writes* are brokered under `withTenant(tenantId, {type:'system'})` after `authorizePortal()`, and live in `modules/*/portal.ts`.
- **Server actions** derive tenant and member from `requireTenantContext()` — never from form parameters.
- **i18n**: no literal JSX strings (ESLint enforces); every key exists in **both** `src/messages/en.json` and `sv.json`, with idiomatic Swedish.
- **UI**: design tokens and existing components only — no raw Tailwind colour utilities, hex literals, or arbitrary radii/shadows/heights. See `docs/UI.md`.
- **Config**: no hostnames or cookie names outside `src/config`; no cookie ever carries a `Domain` attribute (INV-D1, CI-enforced).
- **The PWA shell caches nothing tenant-scoped** (ARC-25): the service worker is network-only for navigations and `/api/*`, precaches only hashed static assets, and neither it nor the manifest is served on the ops host. Offline is v1.5 and needs its own security pass first.
- **Nothing tenant-specific in schema or UI.** If only Naxdor needs it, it is a `TenantPreference`.

## Rules for automated agents

- **The repository is PUBLIC** (founder decision, 2026-09-13 — PLAN §0). Every commit, every doc and every GitHub Actions log line is world-readable. GitHub masks a secret only as its whole string, never a value derived from it: register a host, endpoint id or other derived value with `::add-mask::` before anything can print it (`neon-smoke.yml` does, because Prisma prints the datasource host). Never attach a self-hosted runner to this repository.
- **Never create users, members, roles, sessions or credentials**, and never write to the database, outside a throwaway tenant your own test provisions and tears down. Never touch the `naxdor` tenant. **`e2e-` is the BROWSER harness's prefix and it is SWEPT BY AGE** — `sweep` deletes any `e2e-` tenant older than its age guard — so a dbtest must NOT use it, or a concurrent e2e run will delete its fixtures mid-test. A dbtest uses its own per-suite prefix and **registers it in `DBTEST_PREFIXES`** (`e2e/fixtures/seed-cli.ts`), which is what lets `sweep-dbtests` collect its orphans; that list is regenerated by the two greps documented beside it, and both are blind to a shorthand `{ slug }` property, so spell the literal out at the `slug:` key. An agent once created an owner-level account in tenant zero to render a page; it had to be revoked.
- **Never print, log or commit** passwords, tokens or cookies.
- **Verify by code, tests and `pnpm build`** — and check **exit codes**, not just output. **A PIPE DESTROYS THE EXIT CODE AND THE BACKGROUND-TASK NOTIFICATION REPEATS THE LIE**: `pnpm test:db 2>&1 | tail -60` reports `tail`'s status, so on 2026-09-23 a run with one failing test was announced as “exit code 0” and the log's own last line said `[exited with code 0]` directly under `[ELIFECYCLE] Command failed with exit code 1` — only reading the text caught it. A pipe also buffers, so a 34-minute run shows nothing until it ends. Redirect to a file, or append `; echo "EXIT=${PIPESTATUS[0]}"`. **To clear a suspected environment flake, `git stash` and re-run against clean `main` — not "re-run it alone".** On 2026-09-22 both of `ordering.dbtest.ts`'s concurrency tests failed on the 5000 ms interactive-transaction budget and failed again in isolation, where the standing note says they pass; stashing the diff reproduced them identically on `main` at `2ad8860`, which is what actually proved it was the transatlantic link and the hour. `DB_TX_TIMEOUT_MS=20000` then gives 17/17.
- Re-audit any data-safety claim independently before repeating it.
- **Independent review before every phase-slice commit** (founder rule, 2026-08-21): run `/code-review` — and `/security-review` whenever the diff touches RLS policies, visibility, the portal, migrations or server actions — through a **fresh agent that has not seen the implementation reasoning**, then fix or explicitly disposition every finding (PLAN §0 records the dispositions). A self-review by the implementing agent is not a review. The first such pass over `83df6ce..2ad8e36` found 36 real items the implementing sessions had missed (PLAN §0 / log 2026-08-21). **Fix commits are phase slices too:** the review of those 36 fixes found three more (a regressed hotkey guard, a trigger that broke project cascade-delete, a dead statement) — never skip the pass because "it is only the fixes".
- **Review agents are read-only** (2026-09-14): they read, grep and run git — never `pnpm typecheck`, ESLint, `pnpm test`, the dbtests, a build or a server. The implementing session runs each gate once and tells the reviewers the result. Five reviewers each allowed to "run typecheck if useful" beside a Turbopack build exhausted the founder's machine twice in one afternoon (Windows commit limit; VS Code's window died of OOM and took the session with it), and no transcript said why. Never run a build while agents are in flight either.

## Standing traps (each cost a real bug — details in `docs/PLAN.md` §0)

- React 19 **resets a `<form action>`** at the start of every action; a native `<select>` inside one will show stale server state. Call the action in a transition with `useOptimistic` instead.
- An action failure must **never look like a revert** — return a typed `ActionResult` and toast it.
- `[&_tr:last-child]:border-0` on a table body **deletes row-level left cues**; use `border-b-0`.
- A `"use client"` module's exported constant interpolated into a **server** component's `className` becomes a throwing client reference.
- State a shared component must reflect is a **required prop** (or its own store), never a default.
- **ProseMirror JSON does not cross a server action unaided.** Node attrs are built with `Object.create(null)`, and React's serialiser cannot encode a null-prototype object — `attrs` arrives as an opaque reference (`"$T"`) and the document is refused. Round-trip `JSON.parse(JSON.stringify(editor.getJSON()))` before sending. Plain paragraphs have no attrs, so this hides until the first heading, link, list or checklist.
- **Never hash a document that has not been through Postgres.** jsonb re-orders object keys canonically, so a hash of what you SENT matches nothing any later read computes. A compare-and-set token must come from `RETURNING`, not from the value you passed in.
- **A global Prisma `omit` reaches the export too.** `src/export/service.ts` dumps every model with a select-less `findMany({})`, so a "just for size" global omit silently empties that column out of the tenant's own data export — and no test there covers work items. Narrow the reads instead. (Prisma also loses the result type through a shared `as const` omit; it must be an inline literal.)
- **A hand-written `Escape` handler can never beat a Radix layer.** Next's React root is `document`, so every React `onKeyDown` runs at document-BUBBLE, while Radix's dismissable layers listen on `ownerDocument` with `{capture:true}` and fire while `defaultPrevented` is still false. `inline-edit.tsx` tries to and loses. If you need Escape, you need a Radix layer or an `exclusive` keyboard scope — never a binding.
- **Two window `keydown` listeners will race over a key SEQUENCE.** `G C` reads as a bare `C` to whichever listener the shell's has already cleared the armed `G` for; the answer is ONE dispatcher that consults the sequence before any scope, not a third listener with a third guard. (An `exclusive` scope stops that dispatcher whether or not it binds anything — register one conditionally and you will kill every key in the app.)
- **cmdk's `vimBindings` defaults to TRUE**, so Ctrl+k inside any `<Command>` means "previous item" and shadows the global ⌘K on Windows and Linux. Pass `vimBindings={false}`. cmdk also preventDefaults ArrowUp/ArrowDown, Home, End and Enter without ever stopping propagation — a window listener must check `defaultPrevented` first. (Our `Command` wrapper now defaults it false.)
- **cmdk's root `onKeyDown` owns Enter, ArrowUp/ArrowDown, Home and End for every descendant of `<Command>`.** A calendar inside it commits the highlighted row when Enter is pressed on a day. A non-list body goes AFTER the cmdk root — `PropertyPicker`'s `footer` — still inside the popover.
- **A Radix `Dialog` with no `DialogTrigger` returns focus to NOTHING on close** (Radix focuses a null trigger), so focus lands on `<body>`, where no suppression guard applies and every single key acts behind any layer still open. Spread `useFocusReturn()` onto its content. The hook captures the origin in `onOpenAutoFocus`, which Radix never dispatches when a child has `autoFocus` — React focuses that child during commit, first — so no `autoFocus` inside one (`keymap.test.ts` scans for it). And a focus RETURN onto a Radix `TooltipTrigger` opens its tooltip, whose layer then eats the next Escape — the shared `TooltipTrigger` wrapper refuses a `useFocusReturn` return (`isReturningFocus`), so never bypass the wrapper with Radix's raw trigger.
- **A Radix popover flips but never resizes.** A tall one opened low in the peek runs off a phone screen with nothing left that can scroll (the peek's `RemoveScroll` and its own): cap it at `max-h-(--radix-popover-content-available-height)` and make the content its own scroller.
- **cmdk's `aria-activedescendant` follows only the member's own steering — measure it in a browser, never read it off the source.** A row cmdk lights by itself (its first-row pick on open or on a search change, a re-pick after the lit row unmounts) is `aria-selected`, but cmdk assigns the attribute inside its layout flush from a DOM that has not re-rendered, so it stays unset or names the row lit before; a controlled `value` never sets it. Only ArrowUp/ArrowDown/Home/End or a click do. Two review verifiers traced cmdk's source to the opposite conclusion and a headless browser disproved them.
- **A `Promise.all` inside a Prisma INTERACTIVE transaction is not safe to grow.** Prisma over the `pg` driver adapter does not serialise concurrent statements on a transaction's one connection — `pg` says so itself ("Calling client.query() when the client is already executing a query is deprecated") — so the legs share a connection and a loser can resolve **`undefined`**. Adding a fifth leg to `getItemDetail`'s four-leg batch (2026-09-22) made `readItemComments` — a function that slice never touched — throw `Cannot read properties of undefined (reading 'length')` on its own `findMany`, in ONE test of a full file and never when that test ran alone. The blast lands in the leg that loses, not the leg you added, so the stack names innocent code. A new read inside an existing transaction goes in SEQUENCE, after the batch, not into it. **A per-code check — `isAuthorized`, `requireAccess`/`hasAccess`, the scope helpers — is never a leg, nor inside a per-element callback like `map`** (`src/authz/authz-batches.test.ts` fails the unit suite on it): await each in turn, because a module gate whose read loses the race fails OPEN. ONE `authorizedCodes` or `resolvePermissions` call may be a single leg — it answers the permission gate only, so it never replaces `requireAccess`/`hasAccess` where the module gates matter; for many codes on all four gates use `accessibleCodes`, which is never a leg.
- **A Prisma `update` with no `select` returns the WHOLE row**, a 512 KB ProseMirror document included, even when the caller discards the result. `transitionState` was doing this on every board drop, bulk change and import.
- **A toast is "outside" every Radix modal layer.** Sonner mounts at the root, so over the item peek or any dialog a toast's action was unclickable (`pointer-events: none` on `<body>`), would have DISMISSED the layer once clickable, and a press on it moved focus out of the trap, which handed it back to the field being typed in with its text SELECTED. `toast-outside.ts`, the `Toaster` wrapper and the `SheetContent`/`DialogContent` wrappers handle all three — never bypass those wrappers with a raw Radix layer.
- **A transition around a server action that revalidates stays pending until the whole revalidated page has re-rendered** — measured at over two seconds on a task page. A key guarded by that `isPending` is dead for the whole window. Guard on the action (and an awaited re-read) instead, and wrap in a transition only where the surface draws from server props that must not look live early (`useTimerCommands`' `inTransition`).
- **The e2e suite REUSES whatever is on its port, and says nothing.** `playwright.config.ts` sets `reuseExistingServer: !process.env.CI`, so if any other process holds 3000 the whole run silently executes against THAT application. Measured 2026-09-21: three consecutive full runs went red — `ERR_CONNECTION_REFUSED`, then the app error boundary, then 130 of 133 timing out — across board, backlog, visibility and the Swedish width walk, none of which the diff touched, while every one of those specs passed in isolation. The page snapshot in `test-results/*/error-context.md` was the **Naxdor marketing site** ("Tjänster / Branscher / Orter"), served on 3000 by something else on the machine. Two hypotheses were raised and disproved first (machine memory; a `Promise.all` on one Prisma transaction), which is the cost of not reading the snapshot immediately: **on a broad, cross-surface e2e failure, open `error-context.md` and check WHICH APP answered before theorising.** Run on a port of your own — `E2E_PORT=3457 E2E_BASE_URL=http://127.0.0.1:3457 pnpm test:e2e`; **both** are needed, because the config derives its URL from `E2E_PORT` while `e2e/global-setup.ts` reads `E2E_BASE_URL` and otherwise falls back to a hardcoded 3000, so `E2E_PORT` alone starts the server on the new port and then signs in against the old one.
- **A RATE LIMIT KEYED ON A REQUEST HEADER IS NOT A RATE LIMIT.** `clientIp` read `x-real-ip` first and fell back to the LEFTMOST `x-forwarded-for` hop — both values the caller writes, since RUNBOOK's deployment forwards only `x-forwarded-for` and nginx's `$proxy_add_x_forwarded_for` APPENDS, making the leftmost entry the client's own contribution. `curl -H 'X-Real-Ip: <random>'` in a loop was a fresh subject with a fresh budget every time, which silently defeated the whole in-process floor on the portal's unauthenticated acceptance page. There is now ONE derivation, `src/lib/client-ip.ts`: count from the RIGHT by `TRUSTED_PROXY_HOPS` (default 1), never read `x-real-ip`, bound the length because the value becomes a Map key an unauthenticated caller can create, and refuse a chain shorter than declared. It is shared with the audit row's `ip` — there were two derivations with OPPOSITE precedences, so a request could be limited under one address and recorded under another. **Two tests had been pinning the forgeable behaviour**, which is the part worth remembering: a test can encode a bug as a contract.
- **A `confirm` ON A NON-DANGER `RowAction` IS DEAD STRING.** `rowActionNeedsConfirm` is `!disabled && tone === "danger" && Boolean(confirm)`, so an item with a question but no `tone: "danger"` acts immediately on the menu click and the question never renders. "Pause access" shipped that way for an afternoon — one click killed a contact's sessions with no prompt. Either the verb earns the danger weight or it acts on one click; there is no middle state.
- **The i18n parity test reads a PLURAL BRANCH's first word as an ICU argument name.** `icuArgs` in `src/i18n/messages.test.ts` matches the first token inside any `{...}`, so `{count, plural, =0 {no tasks} ...}` versus `{... =0 {inga uppgifter} ...}` fails as a mismatched argument between locales. Every plural in the catalogue starts its branches with a digit or `#`, which is why nobody had hit it. Put a zero case in the ACTION as its own message instead of contorting the copy.
- **Never run `pnpm build`, `pnpm start` or the e2e suite while `next dev` is running.** The production build rewrites `.next` underneath the dev server, whose browser runtime then requests chunks that no longer exist and reports only "An unexpected Turbopack error". Stop the dev server first; if it happens, kill the process, `rm -rf .next`, and restart. Background dev servers survive killing the `pnpm` wrapper — check with `netstat -ano | grep LISTENING`.
