# Fortleva Design Specification v1.0

**Status:** normative. Implementation agents follow this literally. Every open question is answered here; do not re-decide.

---

## 1. Direction

Fortleva is a tool people live in for eight hours a day, so the interface must be **quiet at rest and loud only where it matters**. The thesis: a near-monochrome, warm-cool-neutral chrome carrying a **single brand accent (deep indigo, hue 268)** restricted to exactly three jobs — filled primary buttons, the active nav indicator, and the focus ring — with all remaining colour delivered by two disciplined systems that are *never* decorative: a **semantic tone set** (six tones, each carrying an icon and a shape so hue is never the only signal) and a **frozen twelve-hue entity palette** that gives every client and project a stable identity dot. Depth comes from a surface ladder plus 1px hairlines, not shadows; shadows exist only for things that genuinely float. Density is deliberate: 13px body on a 4px grid, 32px controls, 36px rows, 16px card padding. **What we are explicitly not doing:** no second accent hue, no gradients, no font-weight above 600, no radius above 12px, no shadows on cards or table rows, no illustrations in empty states, no emoji as icons, no zebra striping, no pure `#000`/`#fff` in dark, no colour-only state, and no tenant branding (the seam is built, Phase 7 uses it).

A tenant whose hue is 25° must not make their primary button read as delete.

### 2.4 The visibility system (safety-critical)

Both states **always** render a chip. Absence is never a state — absence is indistinguishable from a bug.

| | Private to team | Client can see |
|---|---|---|
| token | `--vis-internal-*` | `--vis-client` / `--vis-client-fg` |
| fill light | transparent | **solid** `oklch(0.772 0.125 70)` #e8a654 |
| fill dark | transparent | **solid** `oklch(0.772 0.125 70)` #e8a654 (identical) |
| text | `--muted-foreground` | `oklch(0.264 0.054 70)` #352002 — **7.37:1** |
| border | 1px `--input` (3:1) | 1px `oklch(0.569 0.115 70)` |
| icon | lucide `lock`, outline | lucide `eye`, **filled** |
| shape | 4px radius, weight 500 | pill (`rounded-full`), weight 600 |
| row cue | none | 2px left border in `--vis-client` on the row/card |

Measured separation, solid-vs-outline: **ΔE_OK 0.234 normal / 0.223 deutan / 0.263 protan / 0.227 tritan**. Two pale tints measure 0.072–0.084 and the current shipped pair measures **1.001:1** — that implementation is the product's worst defect and is replaced wholesale.

*Deviation from research 3 (teal):* under deutan/protan the space collapses to a blue↔yellow axis, so placing brand (cool 268) and client-visible (warm 70) at opposite ends is the only arrangement where hue still helps. *Collision rule:* the warm band is the **caution family**. A **filled warm pill** means "Client can see" and nothing else, product-wide. `warning` never renders as a filled pill — only as a tinted surface + 1px border + `triangle-alert`. Enforce with a lint tripwire. Never render the visibility chip icon-only, and never make its mutation optimistic.

### 2.6 Deterministic entity colour

Twelve hues at 15°, 45°, 75°, 105°, 140°, 168°, 196°, 225°, 255°, 285°, 315°, 345°, each anchored to exactly **3:1 against its theme surface**.

```ts
// src/design/entity-color.ts  — pure, RSC-safe, no Math.random, no Date
export const ENTITY_HUES = [15,45,75,105,140,168,196,225,255,285,315,345] as const;

export function entityHash(key: string): number {
  let h = 0x811c9dc5 >>> 0;                       // FNV-1a 32-bit
  for (let i = 0; i < key.length; i++) {
    h ^= key.charCodeAt(i);
    h = Math.imul(h, 0x01000193) >>> 0;
  }
  return h % ENTITY_HUES.length;                  // N = 12
}

/** Always pass the IMMUTABLE id (cuid). Name is a last-resort fallback
 *  for optimistic rows only, reconciled on the server response. */
export function entityIndex(id: string | null | undefined, name: string) {
  return entityHash(id ?? name);
}
```
Light dots (3:1 on white): `#f96176 #f26d21 #c68922 #a09822 #3faa21 #25a882 #25a5a6 #24a1c8 #4696f8 #9087f8 #cf68f9 #f656bc`.
Dark dots (3:1 on `--card`): `#c11b44 #a44713 #855b13 #6c6612 #287212 #167156 #166e6f #166c87 #1363ba #6547e0 #992fc0 #b71c86`.
Exposed as `--entity-0 … --entity-11` in both themes. Distribution over 5000 synthetic keys: 393–453 per bin against an expected 417 — no modulo correction needed. Entity colour is **identity, never status**; the label always carries meaning.

### 2.7 Contrast test (release gate)

`src/design/contrast.test.ts` parses `globals.css` itself (brace-balanced scan of `:root` and `.dark`, iterative `var()` resolution with a cycle guard, OKLCH→OKLab→LMS→**clamped** linear sRGB→relative luminance) and asserts a declarative table. Required rows: `muted-foreground` × {background, card, popover, muted, each -100 tint}; placeholder × {background, card} ≥4.5; `input` × {background, card, muted, popover} ≥3; `ring` × {background, card, primary} ≥3; `primary-foreground` × `primary` ≥4.5; `destructive-foreground` × `destructive` ≥4.5; each `<tone>-800` × its `-100` ≥4.5; `vis-client-fg` × `vis-client` ≥4.5; every `chart-N` × background ≥3 and every `chart-N`×`chart-M` pair ≥3; dark ΔL(background, card, popover) ≥0.04. Plus a CVD table using Machado 2009 severity-1.0 matrices in linear sRGB: ΔE_OK ≥0.15 between the two visibility fills and ≥0.10 between adjacent chart series, for normal/deutan/protan/tritan.

| body strong | `text-sm font-medium` | 13 | 20px | 500 | 0 |
| secondary / hint | `text-xs` | 12 / 0.75 | 16px | 400 | 0 |
| caption, badge, kbd, mobile tab | `text-2xs` (new) | 11 / 0.6875 | 14px | 500 | +0.005em |
| table header, eyebrow | `text-2xs uppercase` | 11 | 16px | 600 | **+0.04em** |
| code / project key | `text-xs font-mono` | 12 | 18px | 500 | 0 |

Tracking values come from Inter's own metric curve (`−0.0223 + 0.185·e^(−0.1745·px)`). The ramp is **bidirectional**: negative above 16px, zero at 13–14px, positive below 12px. Weights are capped at **600**; 700 and 300 do not exist in this product. Hierarchy is size + colour; three foreground tokens per view maximum (`--foreground`, `--muted-foreground`, plus one tone). Delete the ad-hoc `text-[0.8rem]`, `text-[10px]`, `text-[11px]` sites in `app-shell.tsx` and `shortcuts-overlay.tsx` — they become `text-2xs`. `--font-heading` is removed (it aliases `--font-sans`, so `font-heading` is a no-op).

### 3.4 Numerals

Add `@utility num { font-variant-numeric: tabular-nums lining-nums slashed-zero; }`. Apply to: every numeric `<td>`/`<th>`, every duration, money value, count, byte size, version number, date, percentage, project key and `<kbd>`. Prose keeps proportional figures. Use `font-variant-numeric`, never `font-feature-settings`. Verify rendering in a real table (Firefox bug 1907191 drops `tnum` in some table contexts).

### 3.5 sv/en formatting

Build `Intl` formatters **once per locale in a module-level Map**, never inside a render or `.map()`. Durations: three formats, never mixed in one column — lists/chips use `Intl.DurationFormat(locale, {style:'narrow'})` → `1h 30m`; a running timer uses `{style:'digital', hoursDisplay:'always', secondsDisplay:'auto'}` → `0:07:05`, re-rendered once per second; decimal hours (`1,5 h`) only where the value multiplies a rate. Feature-detect `typeof Intl.DurationFormat === "function"` and keep the ten-line fallback. Money: always `Intl.NumberFormat` with an explicit currency — sv-SE default (`1 234 567,50 kr`), en forced to `currencyDisplay:'code'` (`SEK 1,234,567.50`); never `narrowSymbol`. **sv-SE's group separator is U+00A0**, so machine output (CSV, filter matching) must use `{useGrouping:false}` and any client-side text match must normalise `\u00A0` → space. sv percent keeps its space (`42 %`). Swedish strings run 10–25% longer — chips and buttons must wrap or grow, never truncate.

## 4. Space, shape, elevation

**Spacing** — 4px grid: `2 4 6 8 12 16 24 32 48`. The 2px step exists only for icon-to-label gaps inside chips. Icon-to-label: 6px at 16px icon / 13px text; 4px at 14px icon / 12px text.

**Control heights** — `xs 24` (icon-only, isolated), `sm 28` (compact / grouped icon buttons), `default 32`, `lg 40` (prominent CTA). Control padding `8px 12px`; small `6px 10px`. Grouped icon buttons are **28px**, never 24px flush (WCAG 2.5.8 spacing clause).

**Row heights** — table/list rows **36px** default, **32px** compact (density toggle), 44px only where a 32px avatar is present. Table header 32px.

**Radii** — explicit integers, not multiplicative: `--radius-sm: 4px; --radius-md: 6px; --radius-lg: 8px; --radius-xl: 12px`. Controls (button, input, select, textarea, checkbox) = 6px. Cards, dialogs, popovers, menus = 10px (`--radius-card: 10px`). Badges/pills/avatars = `rounded-full`. **Nothing above 12px.** Delete `rounded-4xl`, `rounded-[4px]`, `rounded-[2px]`, `rounded-[min(...)]`, `rounded-[calc(...)]`.

**Border vs shadow** — one surface language: **`1px solid var(--border)`**. The `ring-1 ring-foreground/10` treatment on card/dialog/dropdown/popover/select is removed. Anchored things (cards, rows, sidebar, inputs, tables) get border + surface step, never shadow. Exactly three shadows, for floating layers only:

```css
--shadow-2: 0 4px 12px oklch(0 0 0 / 0.50);
--shadow-3: 0 16px 40px oklch(0 0 0 / 0.60);
```

**Layout frame** — rail 48px collapsed / 224px expanded, user-toggleable at **every breakpoint ≥768px** (fix: the current `w-12 xl:w-56` leaves 768–1280px permanently icon-only with no escape). Header 48px, sticky, `bg-background/95 backdrop-blur`. Mobile bottom tabs 56px. Content: `--content-form: 720px` (settings, account, auth, single-column forms), `--content-default: 1080px` (list and detail pages), `--content-wide: 1440px` (tables, board, backlog). `Page` takes `width="form" | "default" | "wide"`, default `"default"`. Page padding `16px` mobile / `24px` ≥768px, `24px` vertical. Card padding **16px** (`--card-spacing: 16px`, `12px` at `size="sm"`); 12px gutters inside cards, 16px between cards, 24px between sections.

## 5. Motion

```css
--dur-instant: 80ms;  --dur-fast: 120ms;  --dur-base: 200ms;  --dur-slow: 320ms;
--ease-out:      cubic-bezier(0.2, 0, 0.38, 0.9);
--ease-entrance: cubic-bezier(0, 0, 0.38, 0.9);
--ease-exit:     cubic-bezier(0.2, 0, 1, 0.9);
```
Exits run at ~⅔ the enter duration. **Animates:** background/border/text colour on hover and press (80ms); opacity + 4px translate on popover, dropdown, tooltip, select (120ms enter / 80ms exit); dialog and command palette (200ms / 120ms); disclosure height (200ms); sheet transform (320ms / 200ms); the toast stack. **Never animates:** table row insert/remove/reorder, sort, column resize, numeric value changes, the kanban board on data refresh (only on user drag), route changes, anything on an interval. Never `transition-all` — enumerate `background-color, border-color, color, opacity, box-shadow, transform`.

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 1ms !important; animation-iteration-count: 1 !important;
    transition-duration: 1ms !important; scroll-behavior: auto !important;
  }
}
```
**1ms, never `animation: none`** — Radix exit transitions wait on `animationend` and would leave dialogs mounted forever. Also export `useReducedMotion()` so the sonner slide, skeleton shimmer and drag ghost opt out at source.

**Loading:** <200ms render nothing. 200ms–1s change only the trigger (swap the leading icon for a 14px spinner in a **fixed-width slot** so the button never resizes). >1s show a skeleton with a 150ms mount delay, matching real row heights and column widths, 5–7 rows, shimmer a single 1.6s pass and off under reduced motion. Long indeterminate jobs (export, zip) get a labelled progress bar with a phase name.

## 8. Dark mode

Dark is a separate design, not an inversion. What genuinely changes: (1) **elevation reverses** — surfaces get *lighter* with height (`d0` sidebar 0.115 → `d1` canvas 0.155 → `d2` card 0.205 → `d3` popover/dialog 0.245), and the contract is ΔL ≥ 0.04, not a contrast ratio. (2) **Shadows stop doing work** — hairlines and surface steps carry elevation; the three shadow tokens are retained for dialogs only and become pure-black at higher alpha. (3) **Chroma drops** — every semantic and entity colour uses its dark twin at 15–25% lower chroma; the twelve entity dots are re-anchored to 3:1 against `--card`, not against the canvas. (4) **Neither pure black nor pure white** — `--foreground` is `oklch(0.968 0.003 268)`, and the darkest surface is L 11.5%. (5) **Borders become opaque**, never `oklch(1 0 0 / n%)`. (6) `color-scheme: dark` is set so native scrollbars, date pickers and autofill follow; `:autofill` is styled explicitly. (7) **Logo/wordmark** — one SVG using `currentColor` for the wordmark and `var(--primary)` for the mark; no second asset, no `<picture>`.

**Toggle: do not add `next-themes`.** The app already persists per-member preferences server-side (`src/preferences/config.ts` carries locale, timezone, weekStart, durationStyle) and the root layout is already a server component that resolves them; next-themes would introduce a second, client-only source of truth that drifts from the server preference and forces a client boundary at the root. Add `theme: "system" | "light" | "dark"` to that same preference, mirrored into a `fl_theme` cookie so the unauthenticated auth pages work.

No-FOUC technique for Next 16 App Router:

```tsx
// src/app/layout.tsx — server component
const pref = await resolveTheme();            // "system" | "light" | "dark", from member pref or cookie
const cls = pref === "dark" ? "dark" : undefined;   // "system" resolves client-side, pre-paint
return (
  <html lang={locale} className={`${cls ?? ""} ${sans.variable} ${mono.variable}`}
        style={{ colorScheme: pref === "system" ? "light dark" : pref }} suppressHydrationWarning>
    <head>
      <meta name="theme-color" content="#f9fafb" media="(prefers-color-scheme: light)" />
      <meta name="theme-color" content="#0a0c11" media="(prefers-color-scheme: dark)" />
      {pref === "system" && (
        <script dangerouslySetInnerHTML={{ __html:
          `(function(){try{if(matchMedia("(prefers-color-scheme: dark)").matches){` +
          `document.documentElement.classList.add("dark");` +
          `document.documentElement.style.colorScheme="dark"}}catch(e){}})()` }} />
      )}
    </head>
    …
```
The script is synchronous and in `<head>`, so it runs before first paint — no flash, on the initial load and on every streamed navigation (the class is set once on `<html>`, which App Router does not remount). When the preference is explicit, the class is server-rendered and no script ships at all. `suppressHydrationWarning` on `<html>` only.

## 9. Accessibility checklist (testable)

1. Body and heading text ≥4.5:1 against every surface it renders on (`--background`, `--card`, `--popover`, `--muted`, `--sidebar`, every `-100`/`-950` tint).
2. `--muted-foreground` ≥4.5:1 on all six of those surfaces, both themes — asserted in `contrast.test.ts`.
3. Placeholder text ≥4.5:1 (no exemption exists under SC 1.4.3).
4. Input, checkbox, switch and select boundaries ≥3:1 (`--input`, not `--border`).
5. Focus indicator ≥3:1 against the adjacent background **and** against the component; `outline: 2px + offset: 2px`; verified on the primary button, on a table row inside `overflow-x-auto`, and on the last table column.
6. No focused element obscured by the sticky header (SC 2.4.11): `scroll-margin-top: 32px` on focusable rows.
7. Every target ≥24×24 CSS px; grouped icon buttons ≥28px (SC 2.5.8 spacing clause).
8. Every state, priority, health and visibility value distinguishable with hue removed — greyscale screenshot of a mixed list is a release gate.
9. The two `VisibilityBadge` states measure ΔE_OK ≥0.15 under normal, deutan, protan and tritan (unit-tested), and differ additionally in fill, icon, weight and row border.
10. Adjacent chart series ≥3:1 against each other and against the plot background; ΔE_OK ≥0.10 under all four vision types.
11. `prefers-reduced-motion: reduce` clamps every duration to 1ms; no `animation: none`; the skeleton shimmer and toast slide opt out in JS.
12. Every icon-only control carries `aria-label` from `t()`, and its tooltip text is the identical string.
13. `role="status"` on success results, `role="alert"` on errors and on `aria-invalid` helper text; `aria-live="polite"` on the AutoForm saved indicator.
